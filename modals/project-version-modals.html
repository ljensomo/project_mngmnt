Status Lifecycle & Versioning Rules
Strict Versioning Guards & Constraints:
  • The One-Draft Rule: You cannot create a new version if the project's latest entry is currently in DEVELOPMENT or PUBLISHED status. The existing milestone package must be completed or deployed first.
  • Auto-Archiving: Flipping any version's status to ACTIVE will automatically transition the project's *previous* active version to ARCHIVED. Only one version can run live at any single moment.
  • Immutable Codes: Once a version string (e.g., v1.2.0) is generated during creation, it is locked. You can modify timelines, descriptions, and statuses, but the calculated SemVer identifier cannot be altered to preserve pipeline tracking data.

Status Definitions

DEVELOPMENT
Active Coding Phase

The version branch is completely open. Features, bug fixes, and source updates are actively being integrated into this build profile.

PUBLISHED
Build Frozen / QA Stage

Code modifications are stopped. The release candidate package has been generated and is undergoing environment testing or code reviews.

ACTIVE
Live in Production

The running build deployed live to end-users. Represents the current stable standard baseline of the project ecosystem.

ARCHIVED
Legacy Record

Deprecated historical release track. Preserved safely to protect data-logging metrics but completely sealed against ongoing workflow edits.

WITHDRAWN
Revoked Branch

Decommissioned or recalled build path. Used when a production version exhibits critical vulnerabilities or show-stopping deployment breaks.
